# Contributing

Write for a reader who is smart, busy, and new to Firstmate.

## Quality bar

- Start with the reader's question.
- Keep one idea per page when possible.
- Link to related pages instead of copying the same explanation.
- Prefer concrete examples over abstract claims.
- Name safety boundaries directly.
- Keep commands copy-pasteable.
- Update `.docs-source.yml` when navigation changes.

## Page shape

Most pages should follow this shape:

1. what this page helps with
2. the smallest mental model that explains it
3. the practical steps or rules
4. links to related pages

## Review checklist

- The audience is clear.
- Links are relative and work from GitHub.
- The page has one `#` heading.
- The page adds knowledge instead of repeating another page.
- Setup and command examples are current.
